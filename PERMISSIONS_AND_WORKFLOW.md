# Permissions and Job Application Workflow

Requirements do not imply active scheduling, resume editing, or submission automation. See PROJECT.md, AGENTS.md, and SKILLS.md.

## Permissions

| Operation | Default | Scope |
| --- | --- | --- |
| Read postings | Automatic within task | Public/designated sources; record URL/time |
| Read personal files | After master selection | Resume/relevant evidence; identity records excluded by default |
| Create/write outputs | Automatic within task | Reports, copies, revisions, records; preserve originals |
| Overwrite master | Explicit approval | Otherwise create new version |
| Delete | Explicit approval | Identify paths; prefer archive; no original cleanup |
| Scheduled search | After configuration | Confirmed targets, locations, sources, frequency |
| Screen/rank | Automatic within task | Explain recommendations and unknowns |
| Tailor | Draft after master selection | True experience; no invented qualifications |
| Upload/save external drafts | Specific approval | Confirm job, files, answers, upload scope |
| Submit | Specific approval | Confirm scope; preserve receipt and result |
| Email/contact recruiters | Explicit instruction | Authorized recipients/content |

## Workflow

1. Collect postings with company, role, location, arrangement, requirements, deadline, URL.
2. Deduplicate and verify availability; avoid repeated applications.
3. Check required conditions, then rank by experience and preferences.
4. Explain recommendations, evidence, gaps, unknowns.
5. Generate drafts, genuine tracked Word revisions, keyword mappings.
6. Validate facts, rendered pages, layout, attachment requirements.
7. Present specific job, clean final previews, answers for approval.
8. Upload/submit within approval; record time, result, receipt, next action.

States: discovered -> screened -> draft -> awaiting approval -> approved -> uploaded -> submitted. Substantive changes invalidate approval. Investigate uncertain outcomes before retries.

## Selection report and options

Include company, role, ID, source/time, location/arrangement, hard conditions, evidence mapping, recommendation reasons, gaps/unknowns, base resume/edits, deadline, history, next action. Closest means experience alignment; geography is separate.

Options support required/preferred/unrestricted titles, synonyms, keywords, seniority, employment type, industries, employers, exclusions, compensation, ranked locations, arrangements, relocation, optional commute. Execution options: sources, frequency, time/timezone, recommendation count, notifications, master, language, page limit. Missing hard conditions require verification. Preference changes do not modify approved materials automatically.

## Resume requirements

- User selects master; filenames do not establish accuracy/recency.
- Employer page limits first; two pages is only a suggested fallback.
- Preserve readable layout; adjust structure/content rather than excessive shrinking.
- Genuine Word Track Changes must support accept/reject; colored text is insufficient.
- Highlight supported keywords in review files; missing capabilities belong in gap report.
- Prepare clean previews before approval; remove revisions, comments, deleted content, review highlights.
- Validate rendered pages and report counts. Preserve employer-required formats.

Per-job outputs: selection report, tracked/highlighted review DOCX, clean DOCX/PDF, change rationale, keyword mapping, validation.

## Tracking and outstanding settings

Record company, role, ID, URL, discovery time, match reasons, master, attachment paths/versions, approval evidence/time, upload/submission times, state, receipt, next action.

Outstanding: targets/industry, location/remote preferences, sources/frequency/time, master, page limit, optional pay and required conditions. No schedule, resume revision, upload, or submission is active.
